# 本机存储维护

## 授权范围

本轮只执行旧 Harness 发布产物清理，以及保留数量规则、低空间提醒。
不迁移或删除桌面业务资料、聊天图片、微信/企业微信数据库、历史会话和业务成品。

以下内容始终保留：当前 `Programs/DeepSeek` 安装、最近有效的回滚备份、
所有 `release-artifacts/runtime-*`、`pinned-source`、当前发布包和构建输入。
测试临时目录不在本轮清理范围内。无发布清单的旧安装保守跳过。

自动模式只允许淘汰超过保留数量的、已经验证的 `DeepSeek.pre-update-*` 备份。
发布包和旧安装器必须使用人工审核的精确清单，不得由定时任务自动删除。

## 安全要求

- 默认只预览。`auto` 与 `execute` 都会真实删除，不能作为实机验收命令。
- 人工执行须绑定审核时的路径、文件身份和当前安装状态；不允许自动扩大名单。
- 当前安装或保留备份校验失败、进程查询失败、路径出现链接、身份变化时，停止删除。
- 删除意图和逐项结果必须持久记录；审计无法写入时不删除。
- 删除不会进入回收站；只允许处理可重建的软件产物，不用于业务数据清理。
- 安全策略拒绝的操作不通过其他 shell、语言或计划任务重试。

## 维护入口

在 Desktop 源码仓库根目录运行。以下示例不是部署完成记录：

```powershell
powershell -NoProfile -File scripts/cleanup-release-storage.ps1
powershell -NoProfile -File scripts/install-storage-guard.ps1 -DryRun
```

人工执行必须先通过 `-WritePlan <新文件>` 保存预览并审核，再用
`-Execute -ApprovedPlan <同一文件>` 执行。预览后当前安装或保留备份身份改变，
须重新预览、重新审核，不能强行继续。

提醒部署使用 `scripts/install-storage-guard.ps1`；卸载其定时入口使用 `-Uninstall`。
只管理精确名称 `DeepSeek-StorageGuard`，未知同名任务不会覆盖。
实机提醒验收使用 `run-storage-guard.ps1 -CheckOnly -NoNotify`（还需提供其必填路径参数），
不使用 `auto` 进行检查。维护工具独立运行，不需要重装或重启 Harness。
