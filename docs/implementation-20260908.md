# Desktop reliability and usage accounting — 2026-09-08

## Implemented in the working tree

- An unexpected engine exit keeps the existing window and page. A normally hidden titlebar action offers an explicit, single-flight restart/reconnect. Confirmation warns users to copy unsent drafts before the page refresh. No messages or business operations are replayed. A later failure fences stale recovery completion; quitting prevents queued restarts.
- Provider probes have an independent 60-second cache. Session writes use a 15-second throttle rather than forcing account probes after every quiet gap.
- The usage worker reads usage-related events only, caches unchanged file summaries, assigns day/month totals using event timestamps, and removes the old 40-session/8-MiB exclusions. Unsupported, malformed, oversized, or timed-out input is marked incomplete. The most recently updated session is labeled honestly; this is not the currently visible session.
- Large and compressed Harness Lab parsing runs in a worker with bounded memory/time. Existing file identity and sandbox checks remain in the parent.

These are file-summary caches, not yet an event-offset SQLite ledger. Changed files are reread. Local token observations are not provider billing authority.
